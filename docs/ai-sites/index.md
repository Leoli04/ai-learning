# AI 资源地图

> 约 5 分钟 · 关键词：AI 站点、资源导航、核实日期

信息不是不够，而是太散：模型在 Hugging Face、论文在 arXiv、榜单在竞技场、教程在某个人的博客里、工具在 GitHub 上。这张地图把值得长期关注的站点按用途收在一起，**每个都写清"为什么值得看"，而不是只丢一个链接。**

下面所有条目都逐条联网核实过可达性，并标注了是否需要代理。用搜索框或标签筛一下就够，不用从头读到尾。

## 关于"需代理"标记

被标记为「需代理」的站点，在国内网络环境下直连不可达（实测表现是连接超时），**不代表站点有问题或不可靠**。这类站点通常是最权威的一批——Hugging Face、arXiv 以外的论文聚合站、竞技场榜单、海外技术社区。

反过来，「直连」标记意味着国内网络可直接访问，包括不少中文站点与国内可直连的海外服务。

## 这份地图会腐坏，所以标注了核实日期

站点会关停、会改名、会被收购。这张地图上就有两个真实例子：

  <table>
    <tr><th>站点</th><th>发生了什么</th><th>现在的地址</th></tr>
    <tr><td>Papers with Code</td><td>2025 年 7 月被 Meta 关停，域名一度跳转到 Hugging Face 的热门论文页</td><td><code>paperswithcode.co</code>（2026 年由 Hugging Face 重建，SOTA 榜回归）</td></tr>
    <tr><td>Datawhale</td><td>最早的 <code>datawhale.club</code> 已不再使用</td><td><code>datawhale.cn</code></td></tr>
  </table>

所以页面顶部保留了「最近核实」日期。看到日期比较久远时，遇到打不开的链接先别急着换站，搜一下它是不是换了域名。

::: tip
这张地图的价值不在于"收集得多"，而在于**每一条都带一句判断**：它适合谁、解决什么问题。如果只想收藏一堆链接，浏览器书签会比它更方便。
:::

这张地图里的站点按用途分七类。其中四类最需要展开讲——**模型与数据、论文与前沿、评测与榜单、学习与社区**，因为它们的用法有明确的顺序和坑，接下来逐个说清。剩下的**工具与框架、资讯与社区、中文生态**，一张表里的一句判断已经够用；而工具这一类的重点不是"收藏哪个站"，而是动手做一遍，所以交给两个系列长文：《DeepSeek Harness 通俗图解》讲 Agent 框架怎么组装，《企业知识库实战》讲 RAG 与检索怎么落地。
