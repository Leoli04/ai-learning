# 切分策略：chunk 怎么切才不丢信息

> 约 9 分钟 · 关键词：chunk、标题层级、父子块、overlap

## 切分的本质矛盾

切分（chunking）这件事看起来像个体力活，其实它要同时满足两个互相拉扯的诉求：

  <table>
    <tr><th>诉求</th><th>为什么</th><th>倾向</th></tr>
    <tr><td><strong>检索要准</strong></td><td>片段越小，向量越"聚焦"，越容易和问题对上</td><td>切小</td></tr>
    <tr><td><strong>理解要全</strong></td><td>片段越大，回答时上下文越完整，越不容易答一半</td><td>切大</td></tr>
  </table>

切小会丢上下文，切大会糊掉语义。**所有切分策略的差别，本质上都是在回答"在哪一刀切下去损失最小"。**

四种策略完整对比：

  <table>
    <tr><th>策略</th><th>做法</th><th>优点</th><th>代价</th><th>适合</th></tr>
    <tr><td>固定字数</td><td>每 N 字一刀，带 overlap</td><td>实现最简单、速度最快</td><td>语义必然被切断</td><td>快速验证阶段，别上生产</td></tr>
    <tr><td>按段落 / 句子</td><td>以换行或句号为界</td><td>句子级语义完整</td><td>块长度极不均，超长段仍要硬切</td><td>通用文档的兜底策略</td></tr>
    <tr><td><strong>按标题层级</strong></td><td>以标题为界切，块内带标题路径</td><td>结构与语义同时保住</td><td>依赖解析阶段能识别标题层级</td><td>制度、规范、手册（首选）</td></tr>
    <tr><td>语义切分</td><td>用模型判断语义边界</td><td>理论上最贴合内容</td><td>慢、贵，结果不稳定</td><td>少量高价值文档</td></tr>
  </table>

对企业知识库来说，**按标题层级切是性价比最高的选择**——前提是第 2 篇那一步把标题层级解析出来了。这也解释了为什么解析和切分必须放在一起设计：解析阶段漏掉的层级信息，切分阶段再也拿不回来。

## 三样东西不能按字数切

  <table>
    <tr><th>内容</th><th>硬切会怎样</th><th>正确做法</th></tr>
    <tr><td><strong>表格</strong></td><td>行与列名分家，数字失去含义</td><td>整表成块，或按行切但<strong>每块都重复表头</strong></td></tr>
    <tr><td><strong>代码 / 命令</strong></td><td>命令被截断，复制出去跑不通</td><td>以代码块为最小单位，整块保留</td></tr>
    <tr><td><strong>编号列表</strong></td><td>"① ② ③" 分散到不同块</td><td>整组列表成块；过长时至少每块带列表标题</td></tr>
  </table>

表格的处理值得再说一句：**一行一 chunk + 重复表头**，往往比整表一块效果更好。因为用户问"500 万以上谁审批"，匹配的是那一行而不是整张表；而重复表头保证了那一行能独立读懂。

## overlap 该取多少

overlap（相邻块的重叠部分）是为了防止"关键句正好落在切分点上"。经验值：

  <table>
    <tr><th>场景</th><th>建议 overlap</th><th>说明</th></tr>
    <tr><td>按段落 / 句子切</td><td>0～10%</td><td>边界本身就在语义处，不需要太多重叠</td></tr>
    <tr><td>固定字数切</td><td>15～20%</td><td>边界是随机的，只能靠重叠补救</td></tr>
    <tr><td>表格</td><td>不重叠</td><td>重叠会造成数字重复，反而干扰计数类问题</td></tr>
  </table>

overlap 太大的副作用常被忽略：**同一个信息在多个块里重复出现**，检索时五条结果其实说的是一件事，白白挤掉上下文预算。

## 一个可以直接抄的默认方案

把上面的结论拼起来，形成一套不需要调参的起步配置：

  1. **先按标题层级切大块**，块内保留标题路径（`差旅管理办法 > 第三章 > 差旅标准`）；
  2. 大块超过 800 字，**再按段落二次切分**，每段的前面继续拼上标题路径；
  3. **表格独立成块**，按行切时重复表头，并把表名写进块首；
  4. **每个块前面补一句来源**（文件名 + 页码 + 章节），后面检索到内容时能直接溯源；
  5. overlap 取 10%，只在同一段落内部生效，不跨段落重叠。

关键在第 1 步和第 4 步：**标题路径 + 来源信息，是块里最便宜也最值钱的"上下文补充"**。它几乎不增加成本，却能让检索命中的片段自己说清"我是什么、我来自哪里"——后面第 07 篇讲的查询改写和 badcase 分析，都要靠这两样东西定位问题。

::: tip
切分没有标准答案，但有明确的判断标准：**把切好的块单独拿出来读，如果读不懂它在说什么，这块就切错了。** 测试方法很土但很有效——随机抽 30 个 chunk，遮住其他内容只看它本身。
:::
