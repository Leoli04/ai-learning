Agent 与工具调用：从"动嘴"到"动手"

约 7 分钟 · 关键词：Function Calling、ReAct、Agent 循环、MCP

模型自己不会"做"，只会"说"

问模型"帮我查下今天上海天气"，它只能生成一段文字。要真正完成，需要三样东西：

  1. 工具（Tool）：一个个真正能执行的函数——查天气 API、读文件、跑 SQL、发邮件；
  2. Function Calling：让模型输出"结构化的调用意图"（如 {"name":"get_weather","args":{"city":"上海"}}），由你的程序去真正执行；
  3. Agent 循环：把执行结果喂回给模型，让它决定下一步，循环往复直到任务完成。

2022 年的 ReAct 论文给这个循环起了个好记的名字：Reason + Act——想一步，动一步，看结果，再想。

MCP：给"外挂接口"定一个 USB 标准

2024 年之前，每接一个工具都要写一份私有适配：A 框架的插件装不到 B 框架。2024 年底 Anthropic 发布 MCP（Model Context Protocol），把"模型 ↔ 工具/数据源"的接口统一起来——工具方实现一次 MCP Server，任何支持 MCP 的 Agent 都能用。可以理解为工具生态的 USB-C 接口。如今主流 Agent 框架（包括 DeepSeek Harness 这类开源 Harness）都已支持。

✅ 三层记忆：RAG 补知识（知道什么）→ Function Calling 补手脚（能做什么）→ Agent 循环补脑子外的"执行力"（怎么把多步任务串起来）。三者叠加，才是 2025 年后"AI 干活"的完整拼图。
